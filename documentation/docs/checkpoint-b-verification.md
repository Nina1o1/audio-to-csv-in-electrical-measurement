# Checkpoint B 验证

## 实现范围

复用现有 M1–M5，在 App 协调层完成最终片段 → M2.parse → M3.applyParseResult；M3.getDraft 和既有订阅提供草稿快照。M1–M5 的 Public Interface、Data Models、标准单位、持久化格式均未改变。

- 实时快照只更新 UI，不解析、不累计转写历史；当前有效录入的最终片段（含空白文本）原对象传给 M2，ParseResult（含 `{}`）原对象传给 M3，由模块决定空输入及空更新行为。
- M1 保证每段完成一次、识别去重及旧物理连接隔离；App 仅消费当前录入上下文一次，保存成功、确认删除、退出语音及卸载后失效。不根据相同文本去重不同录入。
- M1 通知期间不嵌套业务变更，App 在微任务中检查当前上下文并路由命令／合并字段。STOP_INPUT 不负责解析，完成事件是唯一解析入口。
- M2、M3、M4 均同步；真实异步风险来自 M1 启动／收尾、微任务及代理登录。无额外任务队列或状态框架。
- 按钮保存／删除在当前录入收尾后执行一个待处理请求；解析失败取消该请求。确认／保存期间拒绝新录入及语音修改。
- M4 保存失败、pending 复用、未知结果核对、历史 CRUD、查询、选择和 CSV 继续使用已有流程。

## 严格 Data Contract 补充

以 Public Interface 和共享 Data Models 为准：TranscriptSegment 只有 text，不添加 id/createdAt；M4 正式保存接口使用 save(InspectionRecord)，不改成 add。

| 数据边界 | 共享类型 | 修复后结果 | 实现与测试 |
|---|---|---|---|
| M1 → App | TranscriptSegment | PASS | M1 正常／中断完成均输出仅含 text 的最终片段，真实模块集成断言其结构。 |
| App → M2 | TranscriptSegment | PASS | 不跳过空白最终片段、不重建对象；集成断言引用一致，冻结输入验证无修改。 |
| M2 → App | ParseResult | PASS | 稀疏标准数值结果，不输出单位或 null；集成断言精确结果与静态共享类型。 |
| App → M3 | ParseResult | PASS | 包含空结果在内均交给 applyParseResult；集成断言引用一致。 |
| M3 草稿状态 | DraftFields | PASS | 唯一草稿归 M3；集成覆盖未更新字段保留、空更新不使失败 pending 失效。 |
| M3 → App（保存） | InspectionRecord | PASS | 校验确认后生成九字段记录；集成检查身份、时间和冻结返回对象。 |
| App → M4 | InspectionRecord | PASS | save 接收 confirmSave 返回原对象；写入内容一致，M4 返回后才 completeSave。 |

M1 错误映射另改用严格字符串枚举守卫，移除错误码 as 断言及 String 强制转换；回归覆盖四种合法错误码和可伪装成合法字符串的对象。

自动化使用浏览器／音频／存储替身，不替代下述真实麦克风验收。

## 真实麦克风清单（尚待人工执行）

前提：同源 HTTPS 页面与已有 `/api/m1/*` 代理已部署，讯飞配置有效；使用桌面 Chrome／Edge，允许必要的浏览器语音服务网络访问。代理部署参考 infrastructure/m1-speech-proxy/README.md。没有提供／调用真实凭据，自动化不代表真机验收。

- [ ] 展开“语音代理访问”，用共享访问口令登录；检查登录成功且口令输入框清空。
- [ ] 开始监听 → 说“开始输入” → 等待录入就绪 → 说完整示例数据 → 说“结束输入”；检查状态、实时文本和最终草稿。另测按钮结束及停顿自然完成。
- [ ] 完整示例：“工单A2301，料号C-045，接触电阻12毫欧，绝缘电阻500兆欧，耐电压1500伏通过，合格”。核对六项字段和标准单位。
- [ ] 新一段说“接触电阻改成15毫欧”；仅对应字段变化，其他字段保留。
- [ ] 手动改料号，再语音补充／修正测量值；确认操作同一份草稿。
- [ ] 说“保存” → “修改” → “保存” → “确认保存”；确认一次写入历史、清空草稿和本次文本，刷新后历史仍在。
- [ ] 说“删除” → “保留”；草稿不变。再说“删除” → “确认删除”；只清空草稿，历史不变。
- [ ] 录入未结束时点击保存／删除；等待最终文本合并后才显示确认。重复点击不重复执行。
- [ ] 拒绝麦克风权限、关闭设备或断网；错误可理解，手动草稿不丢失。中断仅保留已确认文本，回到 IDLE 后可重新启动。
- [ ] 录入中说含“保存／删除”的普通正文，不触发草稿操作；确认弹窗期间尝试开始录入，应拒绝且保留草稿。
- [ ] 关闭／重开页面，检查麦克风资源释放及没有重复监听；代理退出后重新录入应要求有效访问会话。
- [ ] 回归手动校验／保存失败重试、历史查询／编辑／删除、选中与全部 CSV 导出。

注意：M1 的 RECORDING 状态包含音频及代理启动阶段，现有公开接口没有独立“音频就绪”事件；首次权限和冷启动延迟不能由 App 伪装成就绪保证。

## 真机反馈与离线回归修复

用户已确认基础语音录入、自动完成、字段修正、保存／删除确认、手动与语音混合编辑、权限拒绝后的手动编辑及恢复权限后的再次录入正常。

关闭 Wi-Fi／拔网线时曾出现超过 10 秒仍停在 RECORDING：浏览器到本机代理的 WebSocket 可以继续存在，不能仅依靠该 socket 的断线事件感知外网丢失。M1 现监听浏览器 offline 通知，沿用 RECOGNITION_FAILED 中断流程，仅输出已确认文本一次，回到 IDLE 并释放资源；网络恢复不自动重启。公开接口及数据模型不变。

新增 6 个 M1 离线测试和 1 个真实 M1 → App → M2 → M3 离线集成场景，覆盖本地 socket 不报错、interim 丢弃、启动结算、监听器清理、迟到回调和联网后显式重启。真实断网场景需在刷新修复后的页面后复测。

全功能本地入口现统一为 `npm run dev:voice` → `https://localhost:5173/`。主 Vue 页面与登录／语音接口同源；独立 M1 验收入口仍默认 8787。旧 HTTP 5173 和旧 8788 的历史保留在各自来源，不自动迁移。
