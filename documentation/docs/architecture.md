# Architecture（修订版）

日期：2026-10-26。已按“安装和实现简单”的原则确定第一版约定；Phase 2 基础配置已完成，页面与业务模块按后续阶段逐步实现。

共享 [Data Models](data-models.md) 原样保留；方法及具体约束见 [Public Interface](public-interface.md)。本文件采纳已讨论的推荐方案，不增加后端、数据库、云同步或全局状态框架。

## 1. 模块边界

```text
麦克风 → M1 → App → M2 → App → M3（唯一草稿）
手动输入 ───────────────→ App → M3
                                 ↓ 待保存记录
历史表格 ← App ← M4 ↔ localStorage
             └→ M5 → CSV 下载
```

所有业务模块之间都经过 App，不互相调用。

| 模块 | 负责 | 不负责 |
|---|---|---|
| M1 | 监听、录入、命令和转写事件、语音错误 | 执行业务命令、解析字段、草稿、持久化 |
| M2 | 单次文本解析、字段提取、单位转换 | 修改草稿、保留历史、保存记录 |
| M3 | 唯一草稿、局部更新、完整校验、确认状态、pending 身份 | localStorage、M4、历史记录编辑、DOM |
| M4 | 初始化、正式记录、查询和 CRUD、存储一致性 | 草稿、生成新记录 ID、UI、CSV |
| M5 | 整批校验、CSV 编码和下载 | 选择记录、查询、存储、修改数据 |
| App | 路由命令、串联调用、UI、选择和查询、编辑副本 | 重做解析、业务校验或直接访问正式存储 |

## 2. 数据归属

- M1 产生 TranscriptSegment，M2 产生 ParseResult；它们都是单次消息，不累计保存。
- M3 独占 DraftFields 和本次 pending record；草稿刷新即丢失。
- M4 独占正式 InspectionRecord[]；只有 M4 访问正式记录存储 key。
- App 管理选中 ID、当前查询、历史编辑表单、提示、加载状态和本次文本展示。
- App 可以保留展示快照及 pending 的协调快照，但不能直接改变模块内部对象。
- InspectionRecord 结构在持久化前表示待保存内容，M4 成功后才作为正式历史记录展示。

## 3. 页面与语音流程

1. 页面立即显示历史表格区域，先呈现“加载中”。
2. App 订阅事件并调用 M4.initialize；成功后显示空集合或记录，失败显示错误并禁写，不能假装没有记录。
3. M3 初始化为空草稿、IDLE。语音可独立尝试启动；不允许自动启动时提供用户按钮。
4. 语音失败不影响手动草稿操作和正常加载的历史功能；M4 初始化失败时可继续编辑草稿，但不能持久化。
5. 实时文本仅展示；最终片段才传给 M2，再在 M3 为 IDLE 时合并。
6. 第一版不累计转写历史；每次录入单独解析，避免反复解析旧值。
7. 录入中禁用页面“监听”按钮，不允许通过该按钮切换监听；用户通过“结束录入”结束本次录入，保留已确认文本并返回监听。M1.stopListening 仍保留底层能力，用于页面退出和异常清理。识别错误不无限重启。
8. App 将录入会话与草稿生命周期关联。开始录入时记录当前上下文；保存、删除或录入失效后，迟到结果不得更新新草稿。
9. 仅在 M3 为 IDLE 时允许开始数据录入。已有录入尚未处理完时，先结束并完成解析合并，再执行保存或删除请求。确认与保存期间禁用编辑和新录入；意外到达的输入明确拒绝并提示，不静默排队覆盖。

会话标记只在内部维护，不给 TranscriptSegment 或其他共享模型增加字段。

## 4. 保存流程

```text
IDLE → requestSave 校验 → CONFIRMING_SAVE
  ↑                         │
  └──── cancelSave ──────────┤
                            ↓ confirmSave
                          SAVING
                            │
                       App 调 M4.save
                ┌───────────┴───────────┐
              明确成功                 明确失败
          completeSave               failSave
          清草稿/pending          保留草稿/完整 pending
                └──────────→ IDLE ←─────┘
```

- 重试未改动的草稿，复用 pending 的全部字段，包括 ID 和时间戳。
- 明确失败后草稿实际改变，旧 pending 失效；下次确认生成新身份。
- 结果不确定保持 SAVING，使用“核对保存结果”：App 换一个 M4 实例重新 initialize，按 pending ID 和完整内容核对磁盘；一致则 completeSave，不存在则 failSave，冲突或读取失败继续冻结。只用原接口，不新增恢复库。
- App 分开处理 M4.save、M3.completeSave 和 UI 渲染异常。不能用一个大 catch 把它们全部视为持久化失败。
- M4 写入成功后才能提示保存成功。当前筛选可能不包含新记录；重查当前条件，并提示“保存成功，该记录不在当前筛选范围内”。
- 单次重试按 ID 幂等；刷新后重新输入相同内容会生成新 ID，不做业务内容去重。

## 5. 持久化与历史操作

固定存储 key 为 inspection-records:v1，内容仍是 InspectionRecord[] 的 JSON，不改变模型。

M4 先构造并校验完整新集合，再序列化和写入；setItem 正常返回后提交内存并通知。通知异常单独处理，不能把已保存操作报告为写失败。通知中的嵌套变更拒绝，避免重入顺序混乱。

存储损坏或读取失败时整体拒绝初始化，保留原数据且禁止写入。不自动修复、不做部分加载、不自动迁移。

历史修改使用 App 的表单副本，确认后才调用 update；失败保留表单。历史删除先确认，成功后清理选中 ID。草稿删除与历史删除完全独立。

每次变更成功重新执行当前查询。筛选、排序和导出不修改正式集合或存储。

## 6. 导出

选中导出从 M4 最新快照按 ID 取数据；全部导出使用 getAll，不受筛选限制。失效 ID 清除，空集合不下载。

M5 固定 12 列，全量验证、CRLF、正确转义，默认 BOM。第一版优先公式防护，接受危险文本在导出时添加单引号；不修改原始记录，不承诺无损往返。

只提示“已发起下载”，不声称已保存到磁盘。

## 7. 技术约束与测试

采用 Vue 3、TypeScript strict、Vite、Vitest 作为第一版工具方案。Vue 只负责页面展示和交互；M1–M5 使用独立 TypeScript，不导入 Vue 或直接操作 DOM。语音首先以桌面 Chrome/Edge 为验收目标，实际检查能力；不支持语音时提供手动功能。Phase 2 已使用现有依赖完成类型、测试和构建验证。

离线范围限定为应用已加载后的手动操作及本地记录管理；第一版不支持离线重新打开，不安装 PWA 或 Service Worker 插件。正式数据受浏览器本地存储生命周期约束。

可以共享纯校验函数，以及用于测试的存储、时钟、ID 和下载适配；不建立额外业务层、事件总线或事务框架。模块状态及方法签名不因测试需要而改变。

| 模块 | 主要测试 |
|---|---|
| M1 | 重复启停、权限失败、迟到回调、最终文本去重、中断保留、正常续接与错误停止 |
| M2 | 稀疏结果、最后有效值、单位转换、缺单位不更新、无效输入、输入不变 |
| M3 | null 语音不清空、手动清空、完整校验、非法状态、取消、pending 复用与失效、快照隔离 |
| M4 | 损坏存储保护、初始化门禁、幂等、先写后提交、写失败、更新白名单、通知异常与重入、查询不变性 |
| M5 | 12 列、特殊字符、公式防护、CRLF/BOM、整批失败、文件名、资源释放 |
| App | 初始化四态、保存失败保留、渲染异常不误报写失败、重查筛选、最新选中导出、旧录入不污染新草稿 |

开发顺序：先补齐验收约定，再做 M4 → M3 → App 手动闭环 → M2 → M1 → M5 和完整集成。M5 可独立提前完成。

## 8. 调整原因与影响

| 调整 | 原因与收益 | 代价及影响 |
|---|---|---|
| 不保留转写历史 | 避免旧文本重解析，简化生命周期 | 不能回看旧片段；更新 User Story TODO，M1/App 行为 |
| 录入中禁用监听按钮 | 按最新页面要求，避免中途切换监听；结束录入使用专用按钮 | 更新 App 按钮状态；保留 M1 底层停止接口 |
| 完整 pending 复用 | 防重复保存和时间戳冲突 | 补充 M3 状态测试；影响 M3/App |
| 隔离通知与渲染错误 | 避免已落盘被误报失败 | 增加异常边界测试；影响模块通知及 App |
| 固定存储格式 | 避免不同实现互不兼容 | 后续版本需显式迁移设计；影响 M4 |
| 非负有限值、独立结果 | 不编造量程或合格阈值 | 若业务标准不同须修订；影响各数据入口 |
| 语音数值和单位成对识别 | 减少数量级误判 | 语音自由度降低；影响 M2，可手动补充 |
| CSV 安全优先 | 降低公式执行风险 | 危险文本可能加单引号；影响 M5 导出内容 |
| 录入会话标记 | 防旧回调污染新草稿 | 少量内部状态；影响 M1/App，不改变模型 |

## 9. 已确定的第一版范围

| 原问题 | 确定答案 | 原因与代价 |
|---|---|---|
| 解析词表 | 固定字段别名、基本中英文结果词、十进制及一千以内常用中文数字；标识符只取已转写的连续 ASCII 字母数字、连字符、下划线 | 本地规则容易测试，无外部服务；复杂口述手动补充 |
| 单位 | 按 Public Interface 的单位表转换，严格区分 mΩ/MΩ | 避免数量级误判；不猜未知别名 |
| 时间 | 存储/接口为 UTC 毫秒格式；页面按设备本地时区显示与输入，并标示时区 | 不安装日期库；严格拒绝歧义或不存在的本地时间 |
| 工单号排序 | 区分大小写的字典序，相同值按 id ASC | 跨环境顺序一致；A10 排在 A2 前 |
| 保存结果不确定 | 用户触发核对，新 M4 实例重新加载；按 ID 和完整内容判定 | 无新接口和依赖；核对失败时必须保持冻结 |
| 自然结束续接 | 1 秒后续接；连续 3 次无新确认结果则停；启动超时 10 秒；有效结果重置次数 | 参数固定、可测试；不保证无限连续录入 |
| 离线重新打开 | 第一版不支持，仅支持已加载页面的手动离线操作 | 不引入 PWA；首次打开及刷新需要可访问页面资源 |

详细词表、换算、错误行为和验收样例以 [Public Interface](public-interface.md) 为准。以上均为产品约定，不代表已经在真实浏览器通过测试；浏览器差异在实现阶段验证，失败走既定降级路径。

## 10. 简单安装与启动方案

- 开发环境使用 Node.js 24.22.1（见 .nvmrc，配合 npm）和桌面 Chrome 或 Edge；Phase 2 使用本机已有的该 Node 版本验证，不修改全局 Node 安装。
- 运行时依赖 Vue 3；开发依赖为 TypeScript、Vite、Vitest 及必要的 Vue 编译、类型检查工具。不引入全局状态框架、UI 组件库或业务解析库。解析、时间、CSV、ID 使用浏览器内置能力和少量本地函数。
- package.json 和锁文件已具备。首次开发安装使用 npm ci，启动使用 npm run dev；检查使用 npm run type-check、npm test 和 npm run build。类型检查覆盖源码、测试及构建配置，当前测试仅覆盖基础层。
- 最终用户通过固定的 HTTPS 地址访问静态网页，无需安装 Node、应用、数据库或插件。本地开发使用 localhost；不以双击 file:// 文件作为支持方式。
- 保持页面来源稳定（协议、主机、端口），避免更换地址后看不到原 localStorage 数据。部署不增加后端服务。

Phase 2 已落地共享类型和公开声明，data model、公开方法签名和状态枚举保持不变；业务模块实现留到后续阶段。原有待定问题已按上述第一版范围关闭。

## 11. 页面要求补充

页面元素、文案、语音命令映射见 [页面要求](page-requirements.md)。前端采用 Vue；草稿与正式记录仍由 M3/M4 独占管理，Vue 响应式状态只保存 UI 状态和模块快照。

已确认：App 仅在 M3 为 IDLE 且未进行结构化处理时开放手动编辑；录音中满足该条件可编辑，解析合并期间暂时禁用。CONFIRMING_SAVE、CONFIRMING_DELETE 和 SAVING 均冻结草稿；选择“修改”或“保留”回到 IDLE 后恢复编辑。该规则不修改 M3 状态机或共享模型。
