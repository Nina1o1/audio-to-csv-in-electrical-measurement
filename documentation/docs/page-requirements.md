# 页面要求（Vue）

日期：2026-10-26。记录已确认的页面设计；当前阶段按用户最新顺序为 Phase 1 静态 UI，验收结果见 [Phase 1 验收报告](phase-1-acceptance.md)。

## 页面布局

页面标题为“工业质检语音录入系统”。语音关键词提示、实时语音转写文本、当前质检草稿、历史记录四个板块依次上下叠放，不改成左右分栏。

### 首屏与视觉层级

- 按用户最新确认，当前质检草稿用浅红色（#fbeaea），其余主板块用浅灰色（#f0f0f0）；板块之间不画分隔线、不加外围边框，不使用装饰图案、渐变或卡片阴影。
- 关键词提示、实时转写文本、当前草稿三个板块必须同时出现在桌面首屏；历史记录排在草稿下方，可以向下滚动查看。
- Phase 1 首屏验收基线为 1366×768 和 1440×900 的浏览器内容视口、100% 缩放；标题、六行草稿及删除/保存按钮均可见。实际测量与截图见验收报告。
- 草稿占前三个板块中最大的面积，目标为其可用高度的一半以上。草稿数值和输入文字优先采用 22–24px，明显大于关键词说明；普通说明文字保持可读，不为挤入首屏而缩小草稿。
- 关键词紧凑分组，转写区域限制展示高度，长文本在区域内滚动，避免把草稿挤出首屏；始终区分 confirmed 与 interim。
- 小屏、较矮窗口或用户放大字体时保留纵向布局、正常字号及完整控件，允许页面滚动，不裁切内容。历史表格在窄屏可横向滚动。
- 输入框和按钮保留必要的控件边界与键盘焦点提示；“无分隔线”针对板块分隔，不取消可访问的交互反馈。

```text
工业质检语音录入系统
├─ 语音关键词提示
│  开始输入 / 结束输入
│  删除 / 保留 / 确认删除
│  保存 / 修改 / 确认保存
├─ 语音录入
│  [开始监听 / 停止监听]  文本状态：空白 / 倾听中 / 文本编译完成
│  [实时转写文本：已确认文本与临时文本分别展示]
│                                               [结束录入]
├─ 当前质检草稿
│  指标名称                 记录             固定单位
│  工单号                   [文本输入]       —
│  零件号                   [文本输入]       —
│  接触电阻                 [数值输入]       mΩ
│  绝缘电阻                 [数值输入]       MΩ
│  耐压                     [数值输入]       V
│  检测结果                 [PASS / FAIL]    —
│                                      [删除]   [保存]
└─ 历史记录
   选择 | 工单号 | 零件号 | 接触电阻 | 绝缘电阻 | 耐压
        | 检测结果 | 保存时间 | 操作（编辑 / 删除）
   [导出选中记录至 CSV]    [导出全部记录至 CSV]
```

关键词提示是说明文字，不做成操作按钮。草稿区始终显示六项指标；历史区从页面初始化开始显示，根据实际状态呈现加载中、空记录、数据或读取错误。

用户于 2026-10-26 确认草稿表格采用“指标名称、记录、固定单位”三列。测量行仅编辑数值，单位列只展示固定文本 mΩ、MΩ、V，不提供单位选择或清空控件，不向草稿或记录增加 unit 属性；其余三行单位显示“—”。数值初始为 null，显示为空。空检测结果显示未选择，不默认设为 PASS。用户同时确认保留结构化处理、确认保存、确认删除及保存期间冻结编辑的现有规则。

历史“保存时间”显示 createdAt；编辑记录更新 updatedAt，不改变原保存时间。排序只开放 M4 支持的工单号和创建时间，默认创建时间降序。

采用浅色填充色块和可读的状态文字，表格用对齐和行间距组织信息；禁用控件显示原因，错误不只依靠颜色。输入框有可访问标签，确认框支持键盘和焦点恢复。

## 页面元素

| 元素 | 要求及调用边界 |
|---|---|
| 语音关键词提示 | 展示下方命令及当前可执行的确认选项；无效状态的命令不执行业务操作。 |
| “监听”按钮 | 切换待机/监听；内容文本处于倾听中（M1 RECORDING）时禁用。底层启动/停止尚未完成时也防止重复点击。 |
| 内容文本 | 实时展示本次 confirmedText 与 interimText；只有最终 confirmed 文本交给 M2，不累计转写历史。 |
| 文本状态 | 按用户指定文案显示“空白”“倾听中”“文本编译完成”；这里的编译完成表示本次转写结束，不代表字段解析或业务校验已通过。 |
| “结束录入”按钮 | 录入中调用 M1.stopRecording，保留已确认文本；完成后返回监听，不关闭监听。其他状态禁用。 |
| 草稿指标表 | 始终显示工单号、零件号、接触电阻、绝缘电阻、耐压、检验结果六项；测量行仅编辑数值。结构化处理中禁用手动编辑。 |
| “删除”按钮 | 删除当前草稿，先 requestDelete，再由用户“保留”或“确认删除”；不影响历史记录。 |
| “保存”按钮 | 校验并请求保存；用户可“修改”或“确认保存”；M4 明确成功后才能清空草稿。 |
| 本地历史表 | 页面初始化即存在，区分加载、空数据、正常、错误；支持修改、删除、查询、排序和选择；确认后才写入。 |
| “导出至 CSV” | 支持导出选中或全部正式记录；由 App 获取最新数据交给 M5。 |

文本状态和结构化处理中标志属于 App UI 状态，不给共享模型新增字段，也不替代 M1/M3 的业务状态。成功保存或确认删除草稿后，文本展示清空；保存失败保留草稿。

## 用户操作与页面行为

| 用户操作或事件 | 页面行为与调用边界 |
|---|---|
| 点击监听 | App 调用 M1.startListening / stopListening；按实际状态更新按钮。倾听中和启动/停止过程中禁止切换。 |
| 说“开始输入” | M1 发出 START_INPUT；App 检查状态后调用 startRecording，实际进入 RECORDING 后显示“倾听中”。 |
| 说“结束输入”或点击“结束录入” | 共用同一结束入口，调用 M1.stopRecording；等待最终片段，保留已确认文本，正常返回监听，不自动保存。 |
| 收到实时文本 | 用完整 confirmedText/interimText 快照更新本次展示，不反复追加，不把临时文本当最终文本。 |
| 收到最终片段 | 显示“文本编译完成”；App 将片段交给 M2.parse，再将结果交给 M3.applyParseResult。结束录入不取消这一步最终解析。 |
| 结构化解析开始 | 禁止手动编辑六项指标，显示“正在结构化解析”。 |
| 结构化解析结束或失败 | 清除处理中标记；M3 为 IDLE 时恢复编辑。失败显示错误，不擅自清空草稿。 |
| 手动编辑 | App 调用 M3.updateField，按返回值或事件更新展示，不直接修改模块内部对象。 |
| 删除草稿 | requestDelete 后显示确认框；“保留”调用 cancelDelete，“确认删除”调用 confirmDelete；只清当前草稿。 |
| 保存草稿 | 先 requestSave 校验；失败显示全部错误，通过才显示确认框。“修改”调用 cancelSave；“确认保存”由 App 协调 M3/M4，持久化明确成功后才提示成功并清草稿。 |
| 编辑历史记录 | 打开独立编辑副本，确认后调用 M4.update；失败保留表单输入和原正式记录。 |
| 删除历史记录 | 确认后调用 M4.delete；成功才移除行并清理已删除的选中 ID，失败保留显示数据。 |
| 排序历史记录 | 调用 M4.query，使用返回快照更新表格，不修改存储。 |
| 导出 CSV | App 从 M4.getAll 取得最新记录，按选择决定集合，再调用 M5.export；无数据不下载，失败显示提示。 |

“开始监听”只开启命令监听，不直接开始采集质检字段。M1 LISTENING 与文本“倾听中”不是同一状态；文本进入“倾听中”以 RECORDING 为依据。

文本状态由事件驱动：页面初始化或草稿清空后为“空白”，录入开始为“倾听中”，收到最终片段为“文本编译完成”（即使最终文本为空）。新一轮录入替换上一轮文本展示，不累计历史。识别中断时按 M1 最终事件保留已确认文本，并单独展示错误；不伪造完成事件。

按钮与语音命令走同一 App 业务入口。录入中点击草稿保存或删除时，先结束本次录入并完成最终解析，再请求确认。通知期间不嵌套变更；延后执行时重新检查状态和录入会话，防止重复点击或迟到事件影响新草稿。

保存结果不确定时保持 SAVING 并提供契约规定的核对流程，不能提示失败后直接生成新记录。历史读取失败时禁写并保留原存储；导出成功只提示“已发起下载”。

## 语音命令

| 用户关键词 | 命令 | App 调用 |
|---|---|---|
| 开始输入 | START_INPUT | M1.startRecording |
| 结束输入（兼容“结束录入”） | STOP_INPUT | M1.stopRecording |
| 删除 | DELETE | M3.requestDelete |
| 保留 | KEEP | M3.cancelDelete |
| 确认删除 | CONFIRM_DELETE | M3.confirmDelete |
| 保存 | SAVE | M3.requestSave |
| 修改 | MODIFY | M3.cancelSave |
| 确认保存 | CONFIRM_SAVE | M3.confirmSave → M4.save → 根据结果 completeSave/failSave |

命令由 M1 识别、App 执行。RECORDING 时 M1 只识别 STOP_INPUT，其余业务命令应在结束录入后说出。按钮提供等价操作，语音不可用时可手动完成流程。

## 已确认：手动编辑的可用时机

用户已确认：仅在 M3 为 IDLE 且未进行结构化处理时允许手动编辑。

| 场景 | 是否允许编辑 |
|---|---|
| M3 为 IDLE，未进行结构化处理（包括录音中） | 允许 |
| 文本解析和草稿合并期间 | 禁止 |
| CONFIRMING_SAVE / CONFIRMING_DELETE | 禁止 |
| SAVING（包括结果待核对） | 禁止 |

用户选择“修改”或“保留”回到 IDLE，且没有结构化处理时恢复编辑。App 控制控件可用性，M3 同时校验自身状态；不能只依赖禁用按钮来保护数据。

该规则保留已确认内容和保存身份，不改变 Data Models、公开方法或状态机。

## 模型说明

emptyDraftFields 仅描述 DraftFields 初始化的空状态，不是独立业务数据；每次初始化或清空创建独立对象。三项测量均为 number | null；语音 null 不清空字段，手动编辑可以清空。

## Phase 2 Mock 交互补充（用户已确认）

- “Mock 测试工具”采用默认折叠的原生 details/summary，可用鼠标或键盘展开。保留模拟命令、预设文本、解析结果、失败与核对入口；移除手动返回启动/保存结果及取消模拟启动控件。不使用真实语音、解析、localStorage 或文件下载。
- 跨筛选不保留不可见记录的选择；查询结果变更后清理对应 ID，并更新数量，不自动恢复原选择。
- 表头全选/取消全选仅作用于当前查询结果；无结果时禁用，部分选中显示半选。
- 导出选中使用有效选择的最新内存示例；导出全部不受查询影响。提示必须说明未实际生成或下载文件。
- 正常 Mock 启动、确认后的保存和首次历史初始化自动完成，不依赖场景结果按钮；保存前检查六项必填、字段类型、有限非负数及 PASS/FAIL。失败和结果不确定仍可通过场景入口预先选择，结构化处理仍通过预设控件演示。手动历史场景仅用于演示加载/空数据/错误，不改查询、编辑或删除规则。
- Mock 不改变三份核心设计文档的业务字段、状态、方法签名或失败规则；完整模块算法及真实能力验证留待后续阶段。
